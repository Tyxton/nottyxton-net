>> FOB_SETUP://INFRASTRUCTURE

Forward Operating Base (FOB): Distributed multi-node cluster provisioning and remote site integration.

>> HARDWARE_MANIFEST

[ ACQUISITION && SPECIFICATION ]

To scale capabilties outside of the primary MSF infrastructure, a secondary site (FOB) is being established. The new cluster comprises three identical Dell XPS nodes designated for an immutable Kubernetes (K3s) control/worker plane, paired with a SFF Lenovo ThinkCentre node acting as a local gateway and Wireguard site-to-site bridge.

[ HARDWARE_UPGRADES ]

Memory density across the Dell XPS cluster was doubled to 32GB per node to ensure adequate scheduling headroom for full container migration. The ThinkCentre gateway was also doubled to 16GB RAM alongside a 2TB local bulk storage drive to buffer telemetry and and state data locally, eliminating total reliance on the primary WAN tunnel to Raiden and Motherbase.

>> TOPOLOGY && ARCHITECTURE

[ CLUSTER_PROVISIONING ]

The three Dell XPS (`fob-k3s-01, fob-k3s-02, fob-k3s-03`) nodes are configured as a strict hardware triplet to support an immutable K3s model. This cluster will be in a development state before being merged into the larger MSF fleet.

The ThinkCenter node (`fob-portal-01`) acts as an edge gateway. Due to environmental constraints, the FOB LAN is connected via Wi-Fi and bridges to the local UniFi Switch 8 over ethernet. The node runs a containerized UniFi Controller to manage the switch and maintain a persistent site-to-site WireGuard tunnel back to the core infrastructure.

[ HOST_NAMING_CONVENTIONS ]

In accordance with MSF naming standards (`[Area]-[Role]-[ID]`), the nodes map to the following nodenames:

  • fob-k3s-01 // Dell XPS Node 1 (Control/Worker)
  • fob-k3s-02 // Dell XPS Node 2 (Worker)
  • fob-k3s-03 // Dell XPS Node 3 (Worker)
  • fob-portal-01 // ThinkCentre Gateway / Bridge

>> IaC

[ OS && DEPLOYMENT ]

All FOB nodes follow the same standardized format of MSF. The base OS being Debian 13, in parallel, these nodes will be additions to the Ansible SSoT monorepo - as well as introduing OpenTofu (Terraform) provisioning workflows for Day-0 infrastructure deployment and automated PXE orchestration.
